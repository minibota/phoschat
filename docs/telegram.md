# Telegram preview

PhosChat uses the Telegram API through the official Telegram Database Library (TDLib). The preview supports sign-in to an existing account, main and archived chat lists, cloud direct and group text messages, and recent history on demand. Use separate PhosChat accounts for separate Telegram sessions.

## Set up an account

1. Install a TDLib JSON shared library at version 1.8.38 or newer. On Debian 13, install `libtdjson1.8.38`. An official Windows build can place `tdjson.dll` beside `phoschat.exe`. Linux packages can provide `libtdjson.so` in the application's library directory.
2. In a build configured with PhosChat's application credentials, open **Accounts**, select **Telegram**, and choose **Save & connect**. Users do not need to register their own Telegram application. Enter your phone number and the verification code requested by Telegram. Two-step verification or email verification may also be required. Use an official Telegram client for registration and device-confirmation flows outside this preview.
3. Leave **Remember this Telegram session** enabled to store its encryption key in the system keychain. Without a working keychain, use a temporary session and sign in again on the next launch.
4. Open a discovered direct or group chat to request its recent text messages in an independent window. Basic groups and supergroups from both the main list and archive are included, without moving chats out of the archive. Discovery continues until Telegram reports that each list is complete. Unfinished discovery resumes after reconnecting.

The published **v0.2.0** installers predate simplified sign-in and still require your API ID and hash. The source now supports bundled application credentials; the next configured official release will provide the simpler flow. See [release configuration](packaging.md#telegram-application-identity).

### Advanced and custom builds

Source builds without application credentials show API ID/hash fields. Obtain your application's values from **API development tools** at [my.telegram.org](https://my.telegram.org). Configured builds expose this option under **Use your own Telegram application (advanced)** when adding an account. Existing accounts keep their original application identity and continue to work after upgrading. [Telegram application registration](https://core.telegram.org/api/obtaining_api_id)

## Session and message data

A session-only account uses a private temporary TDLib profile. Every new session profile receives a random 256-bit encryption key generated by the operating system. Remembered sessions store that key in the system keychain, separately from public application configuration. An application API hash embedded in a desktop binary is extractable and is never used as the new profile encryption key.

Older v0.2.0 profiles are upgraded without deleting their session. Before opening the old profile, PhosChat saves a versioned keychain record containing the new random key and the old key as a temporary fallback. TDLib opens with the new key first and falls back to the old key only on an invalid-key response. Once authorization is ready, it changes the database key before loading conversations. An expired session can complete normal sign-in first. Keeping both keys until successful completion allows recovery after interruption. A keychain failure prevents an unsafe migration. [TDLib database encryption](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1set_database_encryption_key.html)

Use **Remove account** to clear the local profile and stored credentials. For server-side revocation, open **Settings → Devices** in an official Telegram client.

TDLib's message database is disabled, and Telegram message bodies shown by PhosChat stay in memory. Recent history is fetched from Telegram when needed. Sign-in codes, two-step verification passwords, and email addresses entered during sign-in are passed to TDLib and omitted from PhosChat settings and logs. Conversation identifiers are scoped to the authenticated Telegram user and the local account.

## Scope and verification

Broadcast channels require official sponsored-message support and remain excluded. Secret chats, attachments, and account registration remain outside the preview. Protected and auto-deleting groups appear in the list, but opening them explains that their messages cannot yet be displayed or sent. Their restricted content is not fetched into local history. The composer currently uses chat-wide send permissions; individual membership restrictions and administrator overrides still need effective-permission handling. Telegram remains authoritative for accepting or rejecting sends. [Telegram API terms](https://core.telegram.org/api/terms)

The adapter tests replay TDLib JSON updates for sign-in, routing, text history, sends, deletion, group discovery, archive pagination, and reconnects. Credential tests use synthetic values and an in-memory keychain to exercise key migration and failure recovery. UI tests cover both source and configured builds. With the official library installed, the native test starts and closes two TDLib clients before supplying initialization parameters. Signing in and exchanging messages with a live Telegram account, including a real profile migration, remains a separate verification step. [TDLib JSON API](https://core.telegram.org/tdlib/docs/td__json__client_8h.html) · [TDLib authorization and chat flow](https://core.telegram.org/tdlib/getting-started)
